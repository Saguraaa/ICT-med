# MedRoute 证据驱动选择性协作：优化与验收方案

日期：2026-11-09。状态：设计完成，尚未实施、训练或开展真实模型对照评测。

## 1. 目标与范围

在当前 MedRoute 上融合三项可独立开关的机制：A 选择性通信与专家召回、B 证据缺口驱动检索、C 证据优先的最终整合。用 MedAgentBoard 的强基线和任务特定评测思想组织实验。最终报告必须给出各模块单独收益、融合收益、移除模块后的变化，以及原始分子/分母、提升率和置信区间。

本文件的阈值是项目建议验收目标，不是论文结果，也不是已取得结果。允许负提升；没有数据填“未测”，不能填 0、估算值或其他论文的结果。

候选路线：

| 路线 | 内容 | 取舍 |
|---|---|---|
| 推荐：分阶段融合 | 先评测，再 A/B，再 C 提示与课程数据，最后可选微调 | 每阶段可回退，先证明协作收益 |
| 直接强化学习 | 复现多模态分诊与整合训练 | 当前文本分诊、训练数据和模型接口不匹配，首期不采用 |
| 先迁移 LangGraph | 先重写编排框架 | 无法单独证明质量提升，增加对照变量，首期保留标准库架构 |

## 2. 已核实的仓库基线

- `medroute.py`：规则预检 → 模型分诊 → 一次检索 → 专家/讨论 → 最终汇总 → 引用与支持性核验；支持 single、fixed_multi、adaptive。
- 每轮专家串行调用，读取不断增长的 `previous_reports`；不存在完全独立的同轮快照。
- `agents.py`：同一模型承担所有角色；Budget 记录调用、token 和请求耗时。
- `retrieval.py`：本地词项检索或 HTTP 检索；证据含来源、更新时间和审核标志。
- `evaluation.py`：只有预期路由匹配与模型调用总数统计，尚非医学质量评测器。
- `data/demo_cases.jsonl`：7 条显式标记合成案例，只能用于流程测试。
- 默认真实输出关闭；知识与风险规则含演示数据。旧 VALIDATION.md 是历史记录，不证明当前凭证、部署或临床数据可用。
- 已存在用户修改：README.md、.env.example、聊天服务与页面相关文件。实施时保留这些修改。

## 4. 目标流程与状态合同

```text
原始消息 → 风险与完整度检查 → 初始检索 → 专家报告
                                              ↓
                         主持人生成结构化缺口与下一步动作
                          ↙            ↓            ↘
                       追问用户      定向补证       相关专家复议
                          ↘            ↓            ↙
                              证据优先的最终整合
                                      ↓
                              引用和支持性核验
```

新增内部结构，作为原有输出的可选扩展，不破坏聊天接口：

- `Issue`：`id, kind, text, affected_roles, evidence_ids, status`。kind 仅可为 patient_fact_missing、knowledge_gap、interpretation_conflict；status 为 open、resolved。
- `ReviewAction`：`action, issue_ids, selected_roles, queries, questions, reason`。action 为 stop、retrieve、reconsult、clarify、handoff；queries/questions 各最多 2 条。
- `EvidenceRecord`：沿用现有证据元数据；新增文档版本/内容摘要哈希。相同 ID 不同内容不得静默覆盖。
- `ReportRecord`：增加稳定 report_id、role、round、addressed_issue_ids；保留所有历史报告用于审计，当前有效报告按角色和问题索引。
- `IntegrationDecision`：每个最终 claim 关联支持/反对的 report_id 与 evidence_id，以及简短采纳理由；不索取或存储内部思维链。

不接受客户端提交的既往模型判断为可信事实。原始用户消息与模型推断分开；未知不转为否认，更正有来源。首期不引入跨患者长期记忆。

## 5. 模块 A：选择性通信与专家召回

### 机制

1. 第一轮保留现有招募，先采用串行执行以隔离因果。相关风险信息始终对所有参与者可见。
2. 后续只向 selected_roles 发起更新；有新证据影响其报告，或存在涉及其角色的开放问题时才召回。
3. 给专家的上下文包含病例事实、自己的最新报告、相关争议、相关证据。按稳定 ID 去重，保留来源。
4. 不以报告相似度或意见一致直接认定正确；高相似度仅用作去重，不能作为删除风险分歧的理由。
5. 最终整合者接收各角色最新有效意见、所有未决分歧及相关证据；完整历史留作审计，不反复传入每个角色。
6. selected_roles 非法、为空但问题未解决时，不默认成功：保守回退原讨论或转人工，并记录回退率。

配置：`COLLAB_POLICY=baseline|selective`，默认 baseline；讨论上限沿用 MAX_DISCUSSION_ROUNDS。不得裁剪风险预检、必要追问和最终核验。

单独实验：A-context（只裁剪上下文）与 A（再裁剪参与者），避免无法区分收益来源。

并行化 P 作为后续独立工程实验：同轮固定快照、预算原子预留、稳定汇总顺序；发现风险停止派发，已在途调用仍计费计量。A 的主验收不混入 P。

## 6. 模块 B：缺口驱动的迭代补证

1. 在现有 moderator 调用内输出 ReviewAction，避免为了规划新增一个常驻 Agent。
2. patient_fact_missing → 返回 clarification；不使用文献替代患者事实。
3. knowledge_gap → 生成最多 2 条独立查询；interpretation_conflict → 先明确能区分结论的证据问题，再检索或召回。
4. 每个请求最多 1 次额外补证轮、每轮最多 2 次检索。保留现有全局 16 次模型调用和 90 秒默认期限；上限相同用于主对照。
5. 新证据经过现有审核和元数据校验，合并后同步更新 allowed_ids；新增证据可被最终 claims 正常引用。
6. 证据总量默认最多 8 篇，单篇限制沿用现有实现；保护已引用和未决风险证据，无法在上限内保留时转人工，不静默截断。
7. 重复查询、没有新增文档、无可用预算时停止补证；开放重要问题不得仅因预算耗尽标记 solved。
8. 低复杂度专家存在知识缺口时也能进入补证路径；不只修改多专家分支。

配置：`EVIDENCE_POLICY=baseline|gap_driven`，`MAX_EXTRA_RETRIEVAL_ROUNDS=1`，`MAX_FOLLOWUP_QUERIES=2`。所有查询与问题 ID、耗时、返回文档 ID 关联。

## 7. 模块 C：证据优先整合与课程数据

### C-prompt（首期必做）

调整 final 提示及结果验证，使其逐条处理支持意见、反对意见和证据适用性；不按票数决定结论。只增加结构化判定与已有调用的输入，不默认再加一层模型。

建立独立的整合挑战集：全部正确、部分错误、多数错误、全部错误/证据不足。专家意见在各变体间冻结，答案和难度标签只给评测器；系统看不到标签。对“全部错误”不能一律要求自主纠正，允许经标注的检索、追问或转人工。

### C-sft（条件阶段，不是首期验收依赖）

在至少 1000 条经审核训练样本、独立验证/测试划分、可微调模型与算力具备后，训练整合者适配器；基础模型、专家和检索保持固定。训练输入是病例、意见、证据，输出是可核查决策。课程顺序从全部正确到冲突/错误意见。另比较相同数据随机顺序训练，以检验课程本身。

训练模型与当前 API 模型不同时，必须增加“相同基础模型未微调整合者”对照，不能把换模型收益归于微调。不满足条件记录“未启动”，不能把 C-prompt 效果称为训练或 RL 提升。

配置：`INTEGRATION_POLICY=baseline|evidence_first|finetuned`。finetuned 未配置时明确报错或记录回退，不静默冒充。

## 9. 数据与实验矩阵

### 数据建设

- 流程层：现有 7 条 demo 加新单元测试，只验软件逻辑。
- 正式文本分诊：建议起步 200 例开发集、400 例封存测试集；后者建议 100 例高风险、100 例事实不全、100 例知识/解释分歧、100 例常规。风险与任务标签可多重标注，主分层固定，报告各层和宏平均，不能宣称代表真实患病率。
- 400 例仅是首轮规模，不保证足够统计功效。根据开发集配对差异、目标效应和高风险置信区间进行样本量评估；若不足，测试前增样或报告证据不足，不以重复调用替代独立病例。
- 由两位具备相关资质的审核者独立标注，分歧裁决；记录来源许可、脱敏和标注版本。按患者、来源及近重复病例分组隔离开发/训练/测试。
- 标注包含：case_id、原始消息、允许就医级别/动作、需追问字段、高风险标签、可接受科室、关键建议与支持证据。参考答案不能进入模型输入或检索索引。
- 可额外做医学 QA 外部效度测试，但用独立 QA 适配器和指标，不能把选择题正确率写成分诊正确率。
- 未连接真实人工服务时，正确提示人工评估可以计动作正确，但不得计为实际转接完成。

### 实验组

| ID | 配置 | 用途 |
|---|---|---|
| S | 当前 single，共同风险/核验环节 | 单专家基线，不冒称一次调用 |
| S3 | 同一专家 3 次采样，统一整合，全部计费 | 控制多花计算的收益 |
| F | 当前 fixed_multi | 固定协作基线 |
| B0 | 当前 adaptive，A/B/C 关闭 | 所有提升率主要分母 |
| A-context | B0＋通信内容裁剪 | A 内部消融 |
| A / B / C | B0＋各单项 | 单项贡献 |
| AB / AC / BC | 各双项组合 | 融合及移除模块对照 |
| ABC | 三项融合 | 最终候选 |

主矩阵 C 指 C-prompt，C-sft 使用独立组名。A/B/C 的贡献既报告“单项对 B0”，也报告“ABC 对移除该模块后的变体”；各项提升不能相加当作总提升。

每组同病例至少 3 次重复，交错随机运行；模型版本、温度、知识库快照、风险规则、全局调用/期限、重试政策、并发度与环境固定。S3 温度策略在开发集选择并记录，不能利用测试答案挑参数。按病例聚类 bootstrap（10000 次）计算配对差值及相对提升 95% CI；重复结果不能当作独立患者扩充样本量。

先跑开发集 20 例成本试点，估算全矩阵开销并设总 token/费用上限，再进行正式实验。费用使用实际账单或带日期的输入/输出/缓存单价；缺单价只报告 token，不能写“免费”。API 凭证不得写入运行清单。

## 10. 指标定义与提升率

1. 动作正确率：符合审核的允许动作集合病例数 / 全部病例数。超时、无输出、结构无效计失败；只有标注允许时追问/转人工才计正确。
2. 高风险召回：及时给出合格紧急升级提示的高风险病例数 / 全部高风险病例数。普通“请找医生”不自动计紧急识别。
3. 覆盖率：完成自动建议病例数 / 全部病例数；同时报告自动建议正确率、追问率、转人工率、错误自动建议率。
4. 证据支持率：独立审核为有原文支持且适用的关键建议数 / 全部关键建议数。无建议记 NA，并同时报告“输出可接受且建议均有支持的病例数 / 全部病例数”，避免靠不回答提高比例。模型 verify 通过率只算过程指标。
5. 纠错率：冻结专家意见中含错误且最终正确处理的案例数 / 含错误案例数；错误采纳率单独报告。
6. 效率：全部尝试的输入/输出/总 token、模型调用、检索调用、总费用、端到端 P50/P95；分成功、失败、转人工分层。另报每个正确完成病例的总成本 = 全部成本 / 正确完成数。
7. 缓存/重试/超时分别记录；所有实验条件共享政策；最终延迟含核验，不能只计专家阶段。

对越高越好的比例指标，设基线 b、候选 o：

```text
百分点变化 = (o - b) × 100
相对提升率 = (o - b) / b × 100%
```

对越低越好的成本、耗时或错误指标：

```text
降低率 = (b - o) / b × 100%
```

基线 b=0 或原始数据缺失，比例记 NA，保留绝对差值及原因。所有报告先汇总原始值再算比例，不平均逐例百分比。负值如实显示。延迟降低率分别使用总体 P50/P95；bootstrap 时重算分位数。

## 11. 建议验收目标（测试集解封前冻结）

以下为研究工程目标，不代表临床安全标准；严格样本证据不足时结论为“证据不足”。

| 模块 | 效果目标 | 共同质量条件 |
|---|---|---|
| A 对 B0 | 平均总 token 降低至少 15%；调用数与时延如实报告 | 动作正确率差值 95% CI 下限 ≥ -1 个百分点 |
| B 对 B0 | 分歧/知识缺口预定义子组动作正确率增加至少 3 个百分点；相对提升另算 | 总体正确率差值 CI 下限 ≥ -1 个百分点；成本增幅必须披露 |
| C 对 B0 | 冻结意见挑战集纠错率增加至少 5 个百分点 | 总体正确率差值 CI 下限 ≥ -1 个百分点；错误采纳不得明显增加 |
| ABC 对 B0 | 总体正确率增加至少 3 个百分点，平均总 token 降低至少 10% | 正确率差值 CI 下限 > 0；同时满足以下风险/覆盖条件 |

共同条件：高风险召回点估计不得下降，差值 CI 下限 ≥ -2 个百分点；覆盖率差值 CI 下限 ≥ -2 个百分点；已知关键风险回归用例全部通过。阈值不能在看过测试结果后放宽。

token 节省需要点估计达标且降低率 CI 下限 > 0；B/C 效果目标同样要求对应差值 CI 下限 > 0。小样本无法满足时增样复验或记证据不足。ABC 未达标不否定单项有效，但不得称完整融合验收通过。

不预设 P95 必然降低：补证可能增加长尾延迟。单独记录是否达到 10% 降低的探索目标，不与主验收混淆。
